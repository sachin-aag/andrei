## Subsystem: AI Chat

**Purpose:** Per-report conversational assistant that can read report context, search attachments, and propose edits.

**Entry point:** `POST /api/reports/[reportId]/chat` — `streamText()` (via `resolveChatLanguageModel()`) with tools from `buildChatTools()`, streamed back with `toUIMessageStreamResponse()`. Sessions/messages persist in `chatSessions`/`chatMessages` and are managed under `chat/sessions/[sessionId]`. Body includes `workspaceChrome`. Document **and** Agent chrome always propose (`ai_fix` comments + red/green marks); nothing lands until Apply / Dismiss.

**Failure telemetry:** Every assistant failure is captured to PostHog as the `ai_chat_failed` event plus an exception, keyed by workspace user id. Server sites (`stream_start`, `stream_error`, `consume_timeout`, `deadline_abort`, `empty_turn` in both the report and analytics routes) go through `captureChatAssistantFailure` (`src/lib/ai/chat/chat-failure-telemetry.ts`) on the shared `posthog-node` client (`src/lib/analytics/posthog-server.ts`). `deadline_abort` is the 270s wall-clock stop (`CHAT_SERVER_ABORT_MS`) — not Cancel, and not a tool-call cap. Client sites (`client_error`, `empty_turn` in `chat-session-host.tsx`) use `posthog-js`. Tag `surface` from the turn's `chatTarget` (Report vs Analytics share one `/chat` host — do not infer from the API path). Tag `site` for the lifecycle step. Await capture (or Next `after()`) so the isolate cannot freeze first. Never let capture throw — it must not mask the original failure.

**Voice dictation:** Mic to the right of the image-attach icon (`ChatVoiceButton` in shared `ChatPanel`). Click to start, click to stop (no VAD). While recording, the control is a larger level wave, the note “Transcript appears when you stop”, a language chevron (MJ: English / हिन्दी / मराठी), and a white `size-7` stop square — not a brand-filled mic. The composer does **not** fill live. It buffers worklet PCM and, after stop, `POST`s windows to `/api/reports/[id]/chat/transcribe` (`application/octet-stream` + `x-voice-languages`); each request wraps LINEAR16 as WAV and runs one Vertex **Gemini** Flash-Lite transcribe (`resolveGoogleLanguageModel`, same WIF as chat) and returns `{ text }`. Longer recordings are sequential 30s chunks, then the joined transcript is applied once. Do **not** call Cloud Speech-to-Text / Chirp — the runtime SA 403s `PERMISSION_DENIED` without `roles/speech.client`. Do not keep an in-memory stream across POSTs. `GET` is auth warmup (204) and also checks the monthly voice-minute cap. A failure toasts once and stops the mic (do not flush again). Monthly transcribed audio is capped on Admin → Limits (`voice-budget`, default 100,000 minutes) and counted as `voice_transcribe` in the AI feature table. MJ languages: `en-IN`, `hi-IN`, `mr-IN` in native script (Devanagari is preferred; romanization is fine). Demo/Convergent: `en-US`. Do **not** translate STT to English. The assistant still replies in English (`LANGUAGE_RULES` in `CHAT_PROMPT_VERSION` / `ANALYTICS_CHAT_PROMPT_VERSION`). Composer typing is locked only while recording. Stub: `ALLOW_TEST_STUB_SPEECH`. Voice toasts never dump gRPC internals.

**Logic in `src/lib/ai/chat/`:**
- `user-intent.ts` — latest-turn classifier (`social` / `read` / `write`). Greetings strip tools; empty sections are not a draft request. Same classifier on Analytics chat. A leading affirmation is stripped and the remainder classified, so "yes put it in the data worksheet" is a write (and is a write outright when the prior assistant turn offered to write). Agent-mode "go for it" / "do it" is write even after a findings dump. Missing-work complaints ("nothing was filled", "why isn't the table filled") are write on Agent (`reason: missing_work`) so Flash-Lite is skipped. Polite leftovers ("can you do the same") are `ambiguous_polite_request` for Flash-Lite; `can` / bare `do` are not lookups. Analytics also treats a worksheet/sheet/column destination as a write. `intentToolAvailabilityRule` says write tools start hidden on a read turn. Agent read keeps them registered; `unsupported_tool` unlocks them on the next step. `resolve-user-intent.ts` runs Flash-Lite for `ambiguous_agent_mode` (plan/outline vs write), `ambiguous_polite_request`, and for Document-chat worksheet-dump phrasing; high-confidence `preferredSurface=analytics` shows a Switch to Analytics button that resends the original request on Analytics. A yes / go for it after that copy is a write. Stub/timeout falls back to the rules decision. Do not fold retrieval policy into that call.
- `system-prompt.ts` — mode-aware prompt (`plan` vs `agent`); `CHAT_PROMPT_VERSION`; search-then-ask `DOCUMENT_RULES`; propose-and-review copy for live report chat; user-intent rules above the drafting guidance. Agent wrap-up and "Changes this turn" stay in document language (no targetField keys, never call it a recipe). Never claim a fill unless a tool this turn returned proposed, drafted, or applied; call `list_suggestions` before treating a prior card as still waiting.
- `edit-policy.ts` — `isWorkspaceChrome` only. Live report chat always proposes.
- `auto-evidence.ts` — kickoff hybrid retrieval (≤1.5s, fail-soft) injected after document rules
- `context-map.ts` — serializes report state + ready docs (sanitized `summary=`) + insertable Analytics plots + open/approved/dismissed AI-card counts
- `tools.ts` — `read_section`, `list_suggestions`, `list_attachments`, `search_documents`, `document_outline`, `read_document_page`, `ask_user`, draft/edit tools, `insert_image` (`chat` / `section` / `analytics`), `plot_measurements` (on for every pack; omit only when embedding Document tools in Analytics chat); sanitizes untrusted metadata here (not in `src/lib/attachments/`). `edit_table` `insert_rows` prefers `afterRowKey` (first-cell text) over `afterRow`. Do not insert `{ banner }` merged group rows (template banners stay). `draft_field` / `propose_edit` / `edit_table` run `groundDraftText` against the citation ledger's served quotes. Frame mode exempts title-page / user-confirmed identity, 1 April–31 March bounds, and facts already in this report (`citation-exemption.ts`); copied attachment facts still need a page in every section. Tables stay strict. QSR identity tables (`qsr-row-grounding.ts`) pair facts to the row's URS-N quote window, reject stock Complies / Section 13 unless the named stage protocol passes that ID, clear unsupported Stage / Section / Remarks instead of blocking the URS copy, pair Qual Docs dates to that document family, and fail closed when the URS or source protocol is attached but unread. `finish_document_review` seeds `reviewedEvidence` (every walked page) so the gate is not limited to the 60-finding sample. Empty ledger or pages with no quotes fail open (investigation and other types stay fail-open). Every pack uses `unsupportedFactPolicy: block` (invented hard facts do not persist; prose leftover `<date>`/`<identifier>`/`<number>` persist after the repair lookup; table leftovers bounce once so a subsequent search can fill them). Analytics `write_column` is not gated.
- `overclaim.ts` — claim-strength gate on every drafted text, **not pack-gated**. The grounding gate checks whether a number sits on a cited page; it cannot see that the sentence around it claims more than the evidence carries. Two shapes are caught: **permanence** ("permanently fixed", "will not recur", "completely eliminates the risk", "100% effective") does **not persist** — `draft_field` / `propose_edit` / `edit_table` return `status: "overclaim"` and the model rewords, once per turn so a false positive cannot loop; **unbounded scope** (a universal quantifier over batches/samples/results plus a compliance verdict — "all batches met all specifications") saves with a `warning`, since it may be legitimate. Detection is sentence-level and deliberately narrow: a quantifier without a verdict ("all 24 batches were reviewed") and an ordinary scoped conclusion ("no adverse impact was identified for batch X") are not flagged. Prompt side is `CLAIM_STRENGTH_RULES` in `system-prompt.ts`.
- `claim-facts.ts` / `evidence-match.ts` / `ground-draft.ts` / `citation-exemption.ts` / `citation-grounding.ts` / `qsr-row-grounding.ts` / `unsupported-facts-repair.ts` — hard-fact extraction (`URS-\d+` first), uFuzzy page matching, misattributed cite rewrite, `unsupported_facts` tool result. Frame mode omits title-page identity, 1 April–31 March bounds, and facts already stated in this report; tables stay strict. Do not skip a whole section. QSR RTM / Operating Range / Qual Docs / References match numbers and descriptions in that row's URS-N window (a neighbour URS on the same page is not enough), allow URS cover / outside-window identity (capacity, MOC) onto the matching row, keep each column-major block's requirement sentences out of the last ID's window and available to every ID in that block (a shared parameter word such as glass or thickness does not veto them; URS-1 does not match URS-13), ignore digits inside URS-N as measured numbers, do not treat a decimal such as 25.0 as a measured zero, reject stock Complies / Section 13 unless the named stage protocol passes that ID, clear unsupported Stage / Section / Remarks instead of blocking the URS copy, and fail closed when the URS or source protocol is attached but unread. Parked `[n]` resolves through the Citations: list. High-collision dates keep the cited file/page (empty quote or many hits) instead of stealing the first SOP/PRQ page; identifier mismatches still move. Uncited numbers do not attach a coincidental ledger page (unique identifier pin and unique same-file hit still retarget). Integer tokens do not match inside decimals (`3` is not `3.2 mL`). A shared parked `[n]` gets a new list line rather than overwriting the other claim. Table grounding passes sibling cells (documentRef) into that ranking. A blocked write runs one closed-set repair search and re-grounds; prose leftover placeholders persist after that lookup when the facts are still missing; table leftovers bounce once (`keepSearchOpen`) and may persist on a same-turn retry. Suggestion cards persist `claimProvenance` and show Traceability. Audit `claim_verified` / `claim_unsupported`.
- `pending-plan.ts` — remaining-section queue on `chat_sessions.pending_plan`. One prompt seeds empty `draftOrder` items; each Agent turn drafts the current item (two adjacent non-inventory sections may share a turn). Persist stamps `continuation`; the client POSTs `CHAT_AUTO_CONTINUE_TEXT` with `autoContinue`. Do not persist “The assistant stopped before finishing” when that next POST will run. Three turns on the same in-progress item without completing it (`CHAT_PLAN_SAME_SECTION_TURN_LIMIT`, including review-only 270s aborts) pause (`same_section_limit`); Resume clears attempts. Cancel (`pauseReason: cancelled`) and a new typed prompt pause the queue. Auto-continue user rows are hidden; one live `ChatPlanProgress` widget tracks `pendingPlan` **below the transcript** (collapsed `N of M — current`, expand for done / running / pending). The chip spins only while the turn is running, shows Paused on Cancel, and hides when the queue is drafted. Working… cannot outlive an idle stream (stale optimistic send overlay). The agent-done notice names the section just finished.
- `document-review.ts` — `planReviewPages` queues objective-matching pages (floor 8; nearby same-file pages only — no leftover pad). ELR inventory then caps at `REVIEW_INVENTORY_WALK_CAP` (48) so a scored CCF flood can drain in one continue; DV catalogs are not inventories. QSR Table 3 / References take the first two pages of each lifecycle file (covers), not the ELR qualification-history scorer. `selectReviewPages` is listing fair-share only (`REVIEW_PAGE_FETCH_CAP`). Transcript-backed batches skip the extract LLM. `continue_document_review` time-budgets ~60s and round-robins batches across attachments with an 8-wide worker pool in one continue. `REVIEW_CONTINUE_DEADLINE_MARGIN_MS` leaves ~45s for finish + `edit_table`. `start_document_review` returns `truncated` / `skippedDocuments`, and `already_complete` when the same `|obj:` just finished (do not reset into another walk). Rehydrate requires finish `status=complete` and `truncated !== true`; `coverageKey` includes the review objective so a finished walk of one section does not skip another. `prepareStep` recomputes `requireInventoryReview` from the live finished key so an empty table after a matching finish unlocks `edit_table` instead of forcing another start.
- `fields.ts` — type-specific editable sections (`chatEditableSections`); tagged `@` sections set chat scope. Do not keep investigation-only constants like `CHAT_EDITABLE_SECTIONS`.
- `mentions.ts` — `@` documents/sections/plots. Scope is `sectionScopeFromMentions` (one tagged section focuses prompt/tools; none tagged = all). There is no composer section dropdown and no `body.sectionScope`. Bare `@` is a hierarchy (Attachments, then Document sections or Data sheets); `mention-menu.ts` builds the folder tree. Typing filters every leaf — do not recap the list at 8.
- `propose-edit.ts`, `session-title.ts`, `access.ts`
- `repair-tool-call.ts` / `clamp-tool-input.ts` — last-resort tool-call repair. A punctuated name is remapped onto a loaded tool; a name that is not loaded this turn (`edit_table` on a read/review step) remaps onto internal `unsupported_tool` so `AI_NoSuchToolError` cannot end the turn. On Agent read, that signal unlocks the registered write tools on the next step. An `InvalidToolInputError` is clamped to the tool's own JSON Schema (maxItems / maxLength / min / max / enum) and retried once. Malformed JSON is not rewritten.
- `message-target.ts` — per-turn Report | Analytics tags on mixed threads (`chat_messages.metadata.chatTarget`, stamped by the route). Legacy rows use `promptVersion` / exclusive tools. Fully unknown history stays untagged.

**Plan-mode allowlist** in `src/lib/ai/chat/document-review.ts`: `read_section`, `list_suggestions`, `list_attachments`, `search_documents`, `read_document_page`, `document_outline`, `read_analysis`, `ask_user`, plus document-review tools. New tools must be added here or they are silently missing in Plan. Analytics worksheet/plot tools stay off this list.

**`read_analysis`** (Document chat, `tools.ts`): reads saved Analytics results, not attachment pages. No `analysisId` returns `buildExcursionComparison` across every saved time series (one row per out-of-band run, oldest first, plus `clean` and `unassessed`); with `analysisId` it returns one series in full. It exists because the context-map findings line is a **shortlist** — `summarizeTimeSeriesForPrompt` shows the top 6 runs by severity while `analysisEvidence` accepts values from *every* run, so without this tool the grounding gate would pass numbers the model could never see. Over `limit` (default `READ_ANALYSIS_MAX_RUNS` 200), runs are selected by severity and then re-sorted into the caller's order (`capBySeverityKeepingOrder`) — first-N truncation is what hid RIG23001's 101-reading event at chronological position 26 of 27. `judgedReadings === 0` returns `unassessed`, never `clean`: no band in force is not a pass. Not a page-locate tool, so it does **not** hide `search_documents`.

**Spectrum:** Document and Agent share `ChatPanel`. Composer/scope/tool changes must cover Document | Agent chrome, `/chat` **and** `/analytics/chat`, prompt versions (`CHAT_PROMPT_VERSION` / `ANALYTICS_CHAT_PROMPT_VERSION`), Plan allowlist, retrieval-policy, already-drafted, stub model, colocated tests, and `AGENTS.md` / this file / `.cursor/rules/chat-and-attachments.mdc`. Voice dictation is that same shared composer control. Removing a control means deleting parsers, prompt copy, switch-section tools, and tests for it — not hiding the UI. Empty-state Document chips are `chat.examplePrompts` on the document type (Purpose & Scope on DV, Define on investigation); Analytics chips stay in `ANALYTICS_EXAMPLE_PROMPTS`. Report and Analytics `stopWhen` is Cancel or the wall-clock deadline — no tool-step cap; abnormal turns abort at `CHAT_SERVER_ABORT_MS` (from request start). Do not persist a continue/re-prompt notice. Loop guards live in `prepareStep`.

**Retrieval:** `searchReportDocuments` (vector + English FTS OR-tokens). Report body is not chunk-indexed. Comprehensive page review is for inventories / open-set drafts, not sentence rewrites; `finish_document_review` caps findings and follow-up turns keep a slim `citationDigest` (`compactChatToolHistoryForModel`). Empty ELR inventory fills need a finished review whose coverage key matches that section (`coverageKeySatisfiesObjective`); a qualification walk does not unlock Associated Instruments, a floor-8 skip of the PRQR does not unlock `edit_table`, preferred PRQR/PMC/QMS files with zero hits still get a stratified sample (not every page of a 200-page CCF), QSR RTM / Operating Range reviews prefer URS filenames and skip URS demotion (a 5.1 URS walk unlocks 5.2–5.6; skipping DQ/IQ covers does not keep `edit_table` locked), scored inventory pages cap at `REVIEW_INVENTORY_WALK_CAP` (DV catalogs do not; QSR Table 3 walks cover pages of every lifecycle file instead of ELR qualification scoring), a truncated matching finish does not `forceStart` again, and adaptive idle still forces `start_document_review`. Finished coverage is rehydrated when the attachment coverage key is unchanged so a zero delta does not force another walk, except explicit pushback (`isRetrievalPushback`) which skips rehydrate — queued inventory keeps comprehensive (`planKeepsComprehensive`). Attachment cover sheets (`divider=true`) are locators, not cited data pages. Search hits include a ready `[filename, p. N]` (or `[filename]` when the page is missing); the saved field converts those to numbered `[n]` markers plus a trailing Citations: list on every pack. Stub chat: `ALLOW_TEST_STUB_CHAT` / `stub-model.ts` — streams a canned reply; cannot assert tool selection. Production write-path grounding incidents replay `edit_table` through `buildChatTools` (`qsr-rtm-draft-replay.test.ts`); do not add a Playwright spec for tool results.

**Citation links:** Clicking `[filename, p. N]` (or numbered `[n]` that maps to a parked source) in the document, chat, or suggestion Sources opens or reuses that attachment's canvas tab and scrolls the PDF to the cited page (`openDocument(id, page)` via `openCitedDocumentOrToast`). Combined `[file A, p. N, file B, p. M]` (two extensions, comma, or semicolon) splits into one link per file (`splitSourceCitationParts` / `sourceCitationLinkSpans`); extra pages of the same file stay one link. Compact `[E-PR-068 and E-PR-071.pdf, p. 1]` splits only when those files are attached or on the citation ledger (`knownFilenames`); otherwise it stays one filename. English `and` titles (`QDF-Filling and capping machine.pdf`) stay one link. An attached file whose basename is exactly the unsplit cite also stays one link (`resolveExactCitedAttachment`). Word preview cannot jump to a page. Missing or ambiguous filenames toast instead of opening. Decorations stay out of saved TipTap JSON. Open attachment canvases stay mounted (`AttachmentCanvasStack`, hidden/inert like Analytics) so switching to Report does not re-parse the PDF; `rememberDocumentPage` records the last visible page without changing the jump `page` prop. Closing the tab (header Close or the tab X) unmounts the preview and restores the last canvas tab you had open; the next open restores that last page. `openDocument(id)` without a page does not reset to page 1.
