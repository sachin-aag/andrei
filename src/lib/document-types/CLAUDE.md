# Document types

Section keys, identity fields, table-column schemas, and form/SOP lineage per document type.
Owned by `getWorkspaceSections(documentType)`; the shared `sectionTypeEnum` includes every family.
Moved out of the root `CLAUDE.md` so it loads only when working under `src/lib/document-types/`.

## Section types

- **Investigation:** DMAIC (`define`, `measure`, `analyze`, `improve`, `control`) plus `conclusion`, plus non-editable `documents_reviewed`, `attachments`, `signature_approvals`. Content types in `src/types/sections.ts`.
- **Design verification:** demo/MJ shape is `purpose_scope`, `references`, `traceability`, `test_methods`, `test_results`, `deviations`, `conclusion`, `approval_signoff`, `appendices`, plus virtual `cover_page` (lives in `reports.metadata`, not `report_sections`). Convergent pack (`buildDesignVerificationDefinition`) is a 9-section Solea DV (`purpose` … `conclusion`, no cover page). Content types in `src/lib/document-types/design-verification/sections.ts` and `src/lib/document-types/convergent/sections.ts`.
- **Quality risk assessment (MJ only):** SOP/DP/QA/010 F02 + F04. Keys are prefixed `qra_` (`qra_approach` … `qra_revision_history`). Identity lives in `reports.metadata`. RPN/RPR are computed in `src/lib/document-types/qra/scoring.ts`, not by the LLM.
- **Equipment lifecycle report (MJ only):** the *periodic* consolidated review of one piece of equipment since its last Periodic Re-Qualification (PRQ) — not an initial qualification protocol (MJ issues URS/FAT/SAT/IQ/OQ/PQ/RTM/VSR/PRQ separately). 22 sections prefixed `elr_` (`elr_objective` … `elr_revision_history`), content types in `src/lib/document-types/elr/sections.ts`. Every evidence table is preceded by an **assessment** (`narrative`: counts, implication, CA/CAPA, product/runtime impact — not a recap that the section was reviewed). Remaining-section must not mark an evidence section done after `edit_table` alone — the assessment (a count in `narrative`, plus `trend` / `overallGrade` / `recommendation` siblings) has to land in the same turn. Access Control also stays incomplete until every annexure Sr. row is copied, including the continuation page of a Page N of M split. Investigation and DV queues are unchanged. After discrepancies, `elr_system_trends` (5.1) recaps every Observations subsection (3.1–3.14) and Discrepancy (4.0) in the table — Purpose and Scope may be skipped — and the narrative names recurring themes plus downtime / availability. `elr_conclusion` (5.3) opens with a bulleted recap of those sections plus 5.1/5.2, then the qualified-state decision. 6.0 (`recommendationNarrative`) names calendar dates (next PRQ, 5.2 target dates) and how often each follow-up runs — “soon” / “as required” is not a schedule; Continue still names the next PRQ date and review frequency. `elr_risk_actions` is the owned, prioritized action list with an overall Low/Medium/High grade. The export template mirrors MJ's own report form F10: `1.0 Purpose`, `2.0 Scope`, `3.0 Observations and Results` (3.1–3.14 carry responsibility, abbreviations and every evidence section; 3.6 Alarm Trends sits above 3.7 Monitoring and 3.10 Breakdowns so those walks cite that table instead of walking the alarm-trend PDF), `4.0 Discrepancy / Deviations`, `5.0 Summary and Conclusion` (`5.1` System Trends, `5.2` Risk Assessment, `5.3` Conclusion), `6.0 Recommendation`, `7.0 Attachments` (rebuilt at Word export from the live file list via `applyElrLiveAttachmentsTable` — `elr_attachments` is not chat-editable and remaining-section must not draft it), `8.0 Revision History`, `9.0 Approval Page` — workspace labels stay unnumbered. Governed by **SOP/DP/QA/014 Validation/Qualification Procedure R04** (Annex 15 / WHO TRS 1019 / ISPE Vol. 5). Note that SOP has **no ELR format** — F09/F10 are the PRQ protocol/report and the ELR is a new Andrei-proposed deliverable, so it needs its own format number under change control before MJ can issue it. Identity (equipment ID, container format, period, cycle, last/next PRQ, SLIA impact class, review frequency) lives in `reports.metadata`; PRQ frequency comes from the VMP (§7.17.2) and only Direct Impact systems carry periodic requalification (§7.1.5). Equipment description (`elr_system_description`) lists stations as numbered or bulleted items under bold sub-headings (a packed paragraph of stations is not the desired shape; a trailing Citations list does not count) and states material of construction (MOC) of product-contact / wetted parts only — omit it for secondary/tertiary packaging equipment; Direct Impact does not by itself require MOC. Periodic Re-Qualification (PRQP/PRQR, §7.17) and Performance Re-Qualification (RQP/RQR, §7.18, event-triggered) are different documents — do not conflate them. One ELR **per container format** — title-page `formatScope` is the source of truth in chat; if it is unset and attachments name both Vial and Cartridge, `ask_user` before drafting Scope (do not pick the first PRQR). `elr_qualification` and `elr_qms` rows carry Format Applicability (Vial / Cartridge / Line-common) and deterministic checks reject a row scoped to the counterpart format. Cross-reference completeness (excursion→deviation, OOT→CAPA, delayed PM→justification, repeat breakdown→CAPA, DI alarm→action, audit anomaly→deviation, change-since-PRQ→change control, qualification-impacting QMS record→qualification history) lives in `criteriaBySection` as deterministic checks on the owning section — there is deliberately **no** in-document reconciliation/gap-summary table duplicating them, and no workspace-facing section numbers. Table column schemas in `elr/matrix-columns.ts` must stay identical to the headers in `templates/mj-equipment-lifecycle-report-template.docx` — a colocated test asserts placeholder/template-data parity in both directions. Rebuild the Word file with `pnpm build-elr-template` (`scripts/build-mj-elr-template.mjs`).
- **Investigation Report DS (MJ only, `failure_investigation_report`):** MJ's Drug Substance investigation — SOP/QA/017 R08 form F01 R01 (the SOP calls it the Failure Investigation Form, hence the internal key and the `fir_` section prefix). It is **not** a variant of `investigation_report` / Investigation Report DP: that one is SOP/DP/QA/008, Drug Product, DMAIC, signed by QC; this one has no DMAIC at all and is signed EU / EU / Production / QA. Both are live; neither replaces the other. This is MJ's first Drug Substance document type — 008, 010 and 014 are all `SOP/DP/QA/...`. `metadata.unit` defaults to `Drug Substance` and is editable; the Word header's Unit row is what separates DS from DP on paper, since both print "Investigation Report" as the title. 20 sections prefixed `fir_` (`fir_event_description` … `fir_attachments`), content types in `src/lib/document-types/fir/sections.ts`. Identity (unit, date of non-conformance, source document no., product, batch, equipment ID) lives in `reports.metadata`. Four fields are picked from fixed lists, never prose, so deterministic checks can assert they were answered: investigation tools (the seven on the form), root-cause classification, root-cause identification group (6M; `no_root_cause` is exclusive), and batch disposition. Impact assessment additionally carries `resultsStatus` (`final` / `interim`) — a `final` status that still refers to testing in progress fails its check. `FIR_ACTION_HEADERS` adds Responsibility and Target Completion Date to R01's bare `Sr No | Action Plan`, and `FIR_CAPA_EFFECTIVENESS_HEADERS` splits R01's merged `Details/Criteria/duration/Remarks`, because an action with no owner and no date cannot be effectiveness-checked. Interim control is required while any corrective or preventive action has a future target date. Table structures follow MJ's own reports where R01 and the filled reports agree: Investigation Team is `Name | Department (Role/Responsibility)` and Chronology is `Activity / Step | Observation / Details` — both two columns, no `Sr. No.`, and the chronology puts clock times in the observation text rather than a column. Three schemas deliberately differ from ERF/26/022 and are asserted by tests: the historic table keeps **R01's** seven prescribed columns (the filled report used an ad-hoc five that dropped Date / Event No. / Batch No., which the deterministic checks depend on), action tables add Responsibility and Target Completion Date, and the effectiveness check splits R01's merged column. Table column schemas in `fir/matrix-columns.ts` must stay identical to the headers in `templates/mj-failure-investigation-report-template.docx` — a colocated test asserts placeholder/template-data parity in both directions. The checked-in Word file `templates/mj-failure-investigation-report-template.docx` already carries the page chrome of a real SOP/QA/017-F01 report (header with the MJ logo, company block and the `SOP/QA/017` / `Unit: Drug Substance` line, footer, styles, theme, fonts, page setup). Tests assert the body geometry: one form table 10440 dxa wide (page 11909 less 720 margins) over four 2610 columns, identity rows using all four as label/value/label/value, every other row a single `gridSpan=4` cell, **section labels bold 12pt and unshaded** (only inner table header rows carry `D9D9D9`), body text 12pt (`sz 24`) justified at line spacing 276, and a separate 5-column approval table at 10457. A `{@tag}` must sit inside a `<w:p>` — docxtemplater replaces the enclosing paragraph, so a bare tag in a cell silently fails to render. Trend prints are parsed into rows at ingest (`src/lib/attachments/table-extract.ts`, healed on demand by `ensureDocumentTablesForReport`); excursions and the time-series figure live in `src/lib/statistical-analysis/`; computed values are grounded in `src/lib/ai/chat/analysis-evidence.ts`. Export run style is `MJ_FIR_DOCX_RUN_STYLE` (`src/lib/export/docx-export-context.ts`), measured off the source report: Times New Roman 12pt, justified narrative, **grey `D9D9D9` table headers** (the shared default is light blue `D9E2F3` — the clearest giveaway a file did not come from MJ), no cell paragraph spacing (it doubled row heights), and `tableWidthPct: "5000"` so inner tables reach the right border.
- **Generic document (demo pack only):** one continuous `body` section (`{ narrative }`). The editor is a US Letter page canvas (visual page separators overlay the same TipTap field — not extra JSON nodes). No criteria, no Criteria tab / Run AI Check. Headings (H1–H3) are enabled for this type only. Word upload is type-owned (`wordImport.kind === "generic_body"`) and does **not** use pack `wordImportEnabled`. Accepting AI suggestions persists TipTap revision marks and exports them as Word tracked changes. Content types in `src/lib/document-types/generic/sections.ts`.
- **Vendor qualification (3xper only):** QAD-SOP-MS-001-F04 Rev 01 for KSM/KRM/critical raw materials. Keys are prefixed `vq_` (`vq_cover` … `vq_scoring`). Content is `{ answers, narrative?, table? }`. The engineer fills Yes/No/N.A. in the editor; chat drafts comments and impurity/CAPA tables. Header Document Number on the form is always `QAD-SOP-MS-001-F04`; Andrei's unique id is `reports.document_no` (VQ number). Rebuild Word with `pnpm build-vq-template`. Schema in `src/lib/document-types/vq/`. Pack notes: `docs/3xper-deployment.md`. Stand-up: `docs/whitelabel-vercel-deploy.md` (Add a customer).
